# مكتبة الشام — متجر ملازم + API + بوت إدارة تيليغرام

هذه حزمة المشروع الكاملة. الواجهة ثابتة وتُنشر على GitHub Pages، والـ API يستخدم Flask وقاعدة بيانات SQL، وبوت تيليغرام يستقبل تحديثاته عبر webhook ويُدير المنتجات والطلبات.

## ما الذي يعمل في المشروع؟

- واجهة عربية RTL متجاوبة بالألوان الكريمية والأخضر والأزرق المخضر.
- كتالوج حي من قاعدة البيانات، مع بحث وفلاتر للمرحلة والفرع ونوع النسخة.
- المراحل: السادس والخامس والرابع الإعدادي والثالث المتوسط. الفروع: العلمي والأدبي والمهني (ويمكن تعيين الفرع «عام» عند الحاجة).
- أنواع الملازم: أصلية ومستنسخة. إضافة المنتجات وصورها وأسعارها عبر بوت تيليغرام.
- سلة تحفظ على الجهاز، وحساب مجموع المنتجات والتوصيل.
- توصيل لكل محافظات العراق؛ أجرة افتراضية 5,000 دينار للطلب. يمكن تعديلها بالأمر `/shipping`.
- الطلب يجري التحقق من أسعار المنتجات وتوفرها على الخادم، لا اعتماداً على السعر الذي يرسله المتصفح.
- يُحفظ كل طلب في قاعدة البيانات ويرسل البوت إشعاراً للمسؤولين.
- إدارة حالة الطلبات، المخزون، الأسعار، إحصائيات أساسية.
- اختيار «الدفع عند التوصيل» أو تسجيل تفضيل «ماستر كارد».

## مهم جداً بخصوص الماستر كارد

لا توجد بوابة تحصيل بطاقة مدمجة لأن ذلك يتطلب حساب تاجر لدى مزوّد دفع يدعم العراق، ومفاتيح API من ذلك المزوّد. في هذه النسخة، اختيار الماستر كارد **يسجل طلباً بانتظار تأكيد المكتبة فقط**؛ لا يتم تحصيل أي مبلغ إلكترونياً، والموقع لا يطلب رقم البطاقة أو CVV. لا تعلن أن الدفع بالبطاقة صار تلقائياً إلى أن تُربط بوابة دفع حقيقية وتُختبر.

## الملفات

- `index.html`, `styles.css`, `app.js`, `config.js`, `products.js`, `favicon.svg`: واجهة الموقع — هذه الملفات يجب أن تكون في جذر المستودع حتى يتوافق النشر مع مسارات الملفات.
- `backend/app.py`: API، وقاعدة البيانات، والتحقق من الطلبات، ونقاط الإدارة، ومعالجة webhook تيليغرام.
- `requirements.txt`: مكتبات Python.
- `render.yaml`: إعداد مبدئي لنشر API على Render.
- `tests/test_api.py`: اختبارات API.

## نشر الواجهة على GitHub Pages

1. فك ضغط الحزمة.
2. ارفع **محتويات المجلد** إلى جذر مستودع `AlshamLibrary`، وليس ملف ZIP وحده، ولا تضع الملفات داخل مجلد متداخل. يجب أن تظهر `index.html` و`styles.css` و`app.js` بجانب بعضها في الصفحة الأولى للمستودع.
3. افتح `Settings → Pages` في GitHub.
4. اختر `Deploy from a branch`، ثم فرع `main` والمجلد `/(root)`، ثم `Save`.
5. بعد إنشاء الـ API، عدّل `config.js` وعيّن `apiBaseUrl` إلى رابط الـ API العام مثل `https://your-api.onrender.com`، ثم ارفع التعديل إلى GitHub. لا تضع أي مفاتيح سرية في `config.js`.

## نشر الـ API

### 1) قاعدة البيانات

أنشئ مشروع PostgreSQL في مزوّد قاعدة بيانات. يمكن تجربة Supabase Free، مع الانتباه إلى أن المشاريع المجانية قد تتوقف بعد أسبوع من قلة النشاط، لذا احتفظ بنسخة احتياطية من بيانات المكتبة. انسخ رابط الاتصال من إعدادات قاعدة البيانات، ويفضل رابط Session Pooler إذا كان مزوّد الخدمة يوصي به.

### 2) خدمة Render

1. ارفع هذا المشروع إلى GitHub.
2. افتح Render واختر إنشاء خدمة من ملف Blueprint أو Web Service من المستودع.
3. إعدادات الخدمة:
   - Build command: `pip install -r requirements.txt`
   - Start command: `gunicorn backend.app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`
   - Health check path: `/api/health`
4. أضف متغيرات البيئة في إعدادات Render:
   - `DATABASE_URL`: رابط PostgreSQL الكامل من مزوّد قاعدة البيانات.
   - `ADMIN_API_KEY`: كلمة سر طويلة وعشوائية للإدارة (استخدم زر توليد سر في Render أو مدير كلمات مرور).
   - `TELEGRAM_BOT_TOKEN`: توكن البوت الذي يعطيك إياه BotFather.
   - `TELEGRAM_ADMIN_IDS`: أرقام حسابات تيليغرام المسموح لها بالإدارة، مفصولة بفواصل عند وجود أكثر من مسؤول.
   - `TELEGRAM_WEBHOOK_SECRET`: سر عشوائي؛ أحرف إنكليزية وأرقام وشرطة وشرطة سفلية فقط.
   - `ALLOWED_ORIGINS`: اجعله أصل الموقع فقط. المستودع الحالي ظاهر على `https://noonery.github.io`، لذلك يضبطه ملف Render على هذا الأصل؛ غيّره إذا كان رابط Pages مختلفاً. عند الاختبار المحلي أضف `http://127.0.0.1:8000` إذا احتجته.
   - `PUBLIC_API_URL`: رابط خدمة Render نفسها مع `https://` وبدون `/` في النهاية. إذا وفّر Render المتغير `RENDER_EXTERNAL_URL` تلقائياً، يمكن حذف هذا المتغير.
5. لا تضع ملف `.env` أو توكن البوت داخل المستودع. لو انكشف التوكن، ألغِه من BotFather وأصدر آخر.
6. بعد تشغيل الخدمة بنجاح، افتح `https://YOUR-API/api/health`. المطلوب أن ترى JSON فيه `"ok": true` و`"database": "connected"`.

**ملاحظة حول المجانية:** Render Free ينام بعد 15 دقيقة دون طلبات ويب، ونظام الملفات فيه مؤقت؛ لذلك قاعدة البيانات الخارجية ضرورية. هذا مناسب للاختبار وإطلاق محدود، لكنه ليس ضماناً لاستمرارية متجر تجاري دون انقطاع. افحص قيود الخطط الحالية قبل الاعتماد النهائي.

## إعداد بوت تيليغرام

1. أنشئ بوتاً من `@BotFather` وخذ التوكن. لا تنشر التوكن في GitHub ولا ترسله في محادثات عامة.
2. افتح إعدادات Environment في Render وأضف `TELEGRAM_BOT_TOKEN` بالتوكن، ثم أعد نشر الخدمة. يحاول التطبيق ربط webhook تلقائياً عند التشغيل. لا تضف رقم المسؤول إلى الآن؛ أمر `/whoami` مصمم ليعمل حتى قبل تفعيل صلاحيات الإدارة.
3. افتح البوت وأرسل `/whoami`. سيعرض رقم حسابك. أضف `TELEGRAM_ADMIN_IDS` في Render بقيمة ذلك الرقم (يمكن إضافة أكثر من مسؤول بأرقام مفصولة بفواصل)، ثم أعد نشر الخدمة.
4. أرسل `/start` ثم `/help` للبوت.

### أوامر الإدارة

- `/whoami` — معرفة رقم حساب تيليغرام (يعمل حتى قبل إعطاء صلاحية إدارة).
- `/start` أو `/help` — القائمة.
- `/add` — معالج تفاعلي لإضافة ملزمة (الاسم، المادة، المرحلة، الفرع، النوع، السعر، الوصف، ثم الصورة اختيارياً).
- `/products` — عرض المنتجات ومعرّفاتها.
- `/price ID 7500` — تعديل السعر.
- `/stock ID on` أو `/stock ID off` — إظهار الملزمة أو إخفاؤها بسبب نفادها.
- `/edit ID title الاسم الجديد` — تعديل حقل. الحقول: `title`, `subject`, `description`, `instructor`, `grade`, `branch`, `kind`.
- `/delete ID` — حذف ملزمة.
- `/orders` — أحدث الطلبات.
- `/order SHAM-YYMM-000001 confirmed` — تعديل حالة الطلب. الحالات: `confirmed`, `preparing`, `shipped`, `delivered`, `cancelled`.
- `/paid SHAM-YYMM-000001` — تسجيله مدفوعاً بعد التحقق الفعلي من وصول المبلغ فقط.
- `/shipping 5000` — تغيير أجور التوصيل.
- `/stats` — إحصائيات مختصرة.
- `/cancel` — إلغاء إضافة ملزمة جارية.

### حالات الدفع

`cod_due` تعني أن الطلب على الدفع عند التوصيل. اختيار الماستر كارد ينشئ الطلب بحالة «بانتظار تأكيد المكتبة» ولا يعني أن البطاقة دُفعت. لا تستخدم `/paid` قبل التأكد من وصول الدفع فعلياً.

## اختبار محلي

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m backend.app
```

ثم افتح `http://127.0.0.1:5000/api/health` لاختبار API محلياً. يلزم إعداد `config.js` إلى `http://127.0.0.1:5000` لتجربة الواجهة مع API المحلي.

## اختبارات السلامة قبل إطلاق الموقع

- أضف ملزمة اختبار من البوت ثم تأكد من ظهورها في الكتالوج.
- جرّب تغيير السعر وإخفاء المنتج ثم إعادته.
- جرّب طلباً بمحافظة عراقية وتأكد من أن الإجمالي = مجموع الملازم + 5,000 د.ع.
- تأكد أن إشعار الطلب يصل إلى جميع أرقام المسؤولين المضافة.
- اختبر الطلب المرفوض إذا المنتج غير متوفر.
- لا تستخدم بيانات زبائن حقيقية في الاختبار، ولا تنشر مفاتيح API أو توكن البوت في GitHub.
